# 合作

本技能用于抽象管理丞相与Luna之间的任务合作。技能正文只定义通用协作规则，具体项目名称，文件内容，业务任务和技术步骤必须由当前任务动态提供，不能固化到技能正文。

## 丞相职责

1. 由丞相负责总体计划，安全边界，任务分配，结果审核，信息汇总，整合和最终交付。
2. 丞相必须保存每个独立任务和中间产物对话的threadId，并在整合前读取反馈。
3. 丞相必须记录任务来源，创建时间，目标，输入范围，允许文件，禁止事项，验证命令，验收标准和交付内容。

## 项目归属

创建任何新对话前，丞相必须先确认主任务所属项目。

1. 丞相必须核对项目名称，项目路径和isGitRepository状态，并取得对应projectId。
2. 项目任务必须使用project任务类型并传入projectId，禁止创建无项目任务。
3. Git项目默认使用worktree环境，非Git项目使用local环境，圣上明确要求直接使用已保存项目时使用local环境。
4. 丞相找不到匹配项目时，必须暂停创建任务并报告项目目标缺失，不能退回无项目模式。
5. 丞相必须保证独立任务，中间产物对话和主任务属于同一项目，除非圣上明确指定其他项目。

## 合作分配

1. 丞相可以自行完成适合当前上下文的工作，也可以将独立工作分配给Luna。
2. 需要委派的工作必须创建为独立Codex任务，并使用Luna模型。
3. 委派提示必须使用中文，并写明目标，输入范围，允许文件，禁止事项，验证命令和交付内容。
4. 委派提示必须明确任务来源为AI创建，不能把AI创建任务伪装成圣上创建。
5. Luna完成工作后，丞相必须读取反馈，再检查实际差异，测试结果和验收标准。

## 引导提问与中间结论

当圣上通过连续提问或引导提问推动丞相分析一个问题时，丞相必须识别分析过程中形成的阶段性结论。

1. 丞相可以自行分析，也可以将分析任务分配给Luna。
2. 每个阶段性结论都必须单独创建一个中间产物对话，并使用Luna模型承载该结论。
3. 中间产物对话必须创建在主任务所属的同一项目目录中，并且必须保存threadId。
4. 中间产物对话必须记录问题背景，分析过程的必要依据，阶段性结论，不确定事项，待圣上确认事项和对后续工作的影响。
5. 丞相可以在主任务中继续回答圣上，但中间产物对话必须作为该阶段性结论的独立记录，并向圣上提供其threadId或可见任务入口。
6. 圣上在主任务或中间产物对话中的回复，都必须由丞相通过threadId读取并汇总到整体任务。
7. 中间产物对话不仅用于索取资料或展示清单，也用于记录通过圣上引导提问形成的所有阶段性结论。

## 中文标题与敏感信息

任务标题使用以下顺序，AI创建tag，任务类型，主题，日期tag，数字tag。日期tag和数字tag必须位于末尾。前面已经出现AI创建tag时，后续任务类型和主题不得再次出现AI。

所有面向圣上的任务标题，格式化标题，清单标题和阶段标题都使用中文。模型名，代码，路径，版本号，数字和缩写按原样保留。密码，密钥和其他敏感信息不得进入标题，任务提示，日志摘要，截图或公开中间产物。

## 并行和依赖

1. 主任务，独立Luna任务，中间产物对话和任务内部派生代理都计入总并行度。
2. 总并行度最多为5，达到5后禁止创建新任务，也禁止通过失败重试绕过限制。
3. 只有文件范围完全不重叠，依赖关系互不阻塞的任务才能并行。
4. 依赖关系未满足时，丞相必须等待前置任务完成审核，不能提前启动后续任务。

## 审核和整合

Luna报告完成后，丞相必须审核实际文件差异，文件范围，验证命令输出，运行日志，安全边界和验收标准。审核通过后才能整合交付。审核未通过时，丞相必须保留任务状态和证据，不能直接归档或宣称完成。

## 中间产物归档

中间产物对话在结论形成后必须保持可见。

1. 圣上明确确认可以归档时，丞相才允许归档中间产物对话。
2. 圣上主动执行归档操作时，丞相才允许归档中间产物对话。
3. 代理完成，丞相读取反馈，审核通过，完成整合或已经向圣上展示结论，都不能单独触发中间产物归档。
4. 圣上尚未确认且没有主动归档时，丞相禁止自动归档，删除，清理或隐藏中间产物对话。
5. 普通工作任务可以在审核和整合完成后按任务规则归档，但中间产物对话必须遵守圣上确认或圣上主动归档条件。

## 交付检查

交付前，丞相必须报告项目归属，任务来源，threadId，实际差异，验证结果，整合状态和所有中间产物的可见或归档状态。只有当项目目标正确，中文标题正确，必要反馈已读取，验证完成，审核完成且归档条件满足时，丞相才能声称任务完成。
