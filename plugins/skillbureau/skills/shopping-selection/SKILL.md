# 选购

把商品推荐做成可复算的筛选任务。先确定平台和登录状态，再建立标准，完成足量去重采样，最后用本地证据支持每项数据和结论。

## 先确定平台并完成登录准备

1. 先从用户要求中确定选购平台。用户明确指定平台时，只使用指定平台，除非用户要求扩展。
2. 用户没有指定平台时，默认使用拼多多、淘宝和京东。
3. 在开始采样前，分别打开每个选购平台的首页或商品搜索页，要求用户在对应页面登录。页面已经登录时，核对登录状态并告知用户可以继续。
4. 用户尚未登录时，停在登录页面并请用户完成登录。用户确认登录后再开始正式采样。不得绕过登录、验证码、风险验证或平台访问限制。
5. 记录最终使用的平台、登录状态、地区或账号造成的价格限制和抓取时间。平台不可访问时保存阻挡证据，并明确说明该平台无法达到样本目标。

## 执行最低采样量

1. 每个选购平台至少采样200个去重后的有效商品或型号规格。该要求按平台分别计算，不得把三个平台的数量相加后冒充每个平台达标。
2. 通用选购和性价比选购在每个平台执行两条采样路线。综合排序采样100个，低价排序采样100个。
3. 用户明确要求质量优先、高品质或最佳质量时，在每个平台额外执行高价排序采样100个。因此质量导向任务每个平台至少采样300个去重商品。
4. 排序路线发生重叠时，重复商品不计入新路线配额。继续向后采样，直到综合排序贡献100个新商品，低价排序贡献100个新商品，高价排序在需要时贡献100个新商品。
5. 使用品牌、型号、核心规格、容量或数量、版本和关键配置建立平台内去重键。同一平台的不同店铺、广告位、活动链接和重复上架不能冒充不同商品。
6. 跨平台同型号在最终比较中合并为一个产品和多个平台报价，不得冒充多个最终候选。各平台的覆盖量仍分别记录。
7. 统计原始浏览数、无效条目数、重复条目数、平台内去重数、跨平台合并数和进入详细核验的候选数。原始清单必须能够逐条追溯。
8. 平台确实没有足够供给时，记录实际可得数量、搜索词、筛选条件、翻页或加载终点和页面证据。不得伪造数量，也不得把重复商品补入配额。

## 建立筛选口径

1. 从用户文字、攻略、规格书或链接中提取硬条件、及格线、理想区间、预算、禁选品牌、禁选店铺和必须选择的规格。
2. 区分硬条件和偏好。任何违反硬条件的商品都不得进入推荐。
3. 保留指标方向和边界。用户设置上限时，不得把更高数值解释成更优。
4. 指标进入理想区间后，不要因为接近区间上沿而自动加分。优先提高综合质量价格比。
5. 未公开或未定量标示的数据记录为未标示。不得把空值当成零、合格或理想。
6. 用户没有提供标准时，根据商品类别建立可解释的性能、安全、用料、耐用、售后和价格标准。重大选择无法合理推断时，只询问一个最关键的问题。

## 记录采样和去重数据

1. 为每条原始商品记录平台、排序路线、路线内位置、平台商品编号、店铺、标题、品牌、型号、准确规格、页面价格、优惠条件、单位价格、原始URL、最终URL和抓取时间。
2. 为每条记录生成平台内去重键和跨平台产品键。重复记录保留原始痕迹，并使用duplicate_of指向被合并记录。
3. 不得声称已经核验无法逐条追溯的数量。缺少原始清单时，只能把数量标记为过程记录，不能用于证明达到最低采样量。
4. 搜索摘要只能作为线索。价格、规格和质量结论必须回到当前交易页面、品牌资料或其他一级来源。

## 核验质量和价格

1. 使用商品详情、品牌规格书、认证资料、检测报告和官方售后条款作为主要证据。
2. 区分保证值、标称值、批次实测值、宣传语和用户评价。不要混用证据等级。
3. 把价格统一换算到相同单位和相同可用数量。明确优惠券、会员、地区、账号、运费、订金和组合装条件。
4. 评分前先执行硬条件筛选。评分权重必须公开，并且适合该商品类别。
5. 质量价格比至少考虑核心性能、用料、可靠性、安全、售后、真实单位价格和证据完整性。
6. 商品质量差异不能被小额价差掩盖。无法证实的宣传点不能获得正向分数。

## 形成推荐

1. 用户要求性价比时，在满足全部硬条件的商品中按照公开权重计算综合质量价格比，并给出主推荐和备选。
2. 用户同时提供及格线和理想区间时，默认给出极致性价比和理想性价比。极致性价比来自满足及格线的商品，理想性价比来自进入理想区间的商品。
3. 用户要求质量优先时，把高价排序路线用于发现高端候选，但价格本身不得作为质量证据。最终质量排序仍然必须依据性能、用料、可靠性、安全、售后和证据。
4. 两类推荐可以是同一商品。候选不足或理想区间没有合格商品时，直接说明缺口，不得强行指定。

## 保存逐项证据

1. 为每项结论分配稳定来源编号。每个价格、规格、性能指标、排除理由和计算结果都必须能回到来源编号。
2. 保存原始URL、最终URL、页面标题、抓取时间、整页长截图、关键数据局部截图和页面DOM或文本快照。
3. 页面包含轮播图、详情图、展开区或分页时，加载并保存所有与判断有关的状态。把连续截图拼成长图，同时保留单张文件。
4. 优先打包页面原始图片和静态资源。资源带临时签名或可能失效时，把资源复制到本地。无法保存原资源时，保存清晰截图裁切。
5. 创建只依赖本地文件的网页快照索引。不要让离线索引依赖外部图标、字体、样式或脚本。
6. 保存结构化清单和SHA256校验值。价格被遮蔽时保留原样，不得推断问号或模糊数字。
7. 旧报告必须作为历史版本保存。新结论不得覆盖或伪装成旧结论。

详细字段和目录建议位于references/evidence-schema.md。需要正式归档时读取该文件。

## 制作比较报告

1. 用表格逐项展示标准、候选数据、比较符号、是否达标、单位价格、证据编号和证据文件。
2. 用柱状图或其他合适图表直观比较关键指标和价格。空值显示为未标示，不得画成零。
3. 同时保存可编辑工程文件和静态截图。报告截图应能独立表达标准、推荐、关键数据、价格和限制。
4. 结论必须给出数据、比较过程和来源。不得只写不符合要求或当前证据不支持。
5. 明确价格观察时间和复核要求。实时价格会随账号、地区和促销变化。

## 交付和浏览器状态

1. 按推荐优先级列出链接。默认先列主推荐，再列理想区间推荐，再列备选。
2. 用户要求打开商品时，在浏览器中按相同优先顺序保留推荐页面，并选择报告对应的准确规格或型号。
3. 选择规格后核对标题、规格、总数量和价格信号。不要停在默认变体或相似商品上。
4. 打开和选择商品不代表购买授权。不得提交订单、付款或发送个人资料。
5. 最终交付应包含平台采样统计、去重清单、结论、结构化数据、引用索引、网页快照索引、关键证据截图、长图、可编辑报告和已知限制。

## 完成检查

1. 选购平台已经确定，并且每个平台的登录状态已经核对。
2. 每个平台已经达到200个去重商品，质量导向任务已经达到300个。供给不足时已经保存数量不足的证据。
3. 综合排序、低价排序和高价排序的路线配额已经分别达到要求，路线重叠已经补足。
4. 硬条件和排除项已经逐条执行。
5. 搜索数量、平台内去重和跨平台合并口径可以复核。
6. 每个展示数据都有来源编号和本地证据。
7. 所有截图、长图和离线链接可以打开。
8. 所有图片都通过解码检查，离线索引没有缺失的本地引用。
9. 推荐页面停留在准确商品和准确规格。
